# Internacionalização (i18n)

[next-intl](https://next-intl.dev) 4, três idiomas: inglês (`en`, padrão), português (`pt`) e espanhol (`es`).

## O que é traduzido

A interface: botões, links, formulários, mensagens de erro, textos oficiais (termos, privacidade, sobre), metadata das páginas e emails.

Não é traduzido: conteúdo dos usuários (perguntas, respostas, bio, nome) e dados do seed. Como em qualquer rede social global, cada um escreve no idioma que quiser. Logs internos (Telegram, console) também ficam como estão.

## Como o idioma é escolhido

Não há idioma na URL (`/login` é a mesma rota em todos). `i18n/request.ts` decide a cada requisição:

1. cookie `NEXT_LOCALE`, gravado pelo seletor (`components/locale-switcher.tsx` + `actions/locale-actions.ts`);
2. sem cookie, o primeiro idioma suportado do header `Accept-Language`;
3. senão, inglês.

As rotas são em inglês (`/my-account`, `/payments`) e iguais em todos os idiomas: prefixo de idioma colidiria com o perfil público em `/[slug]`. As rotas antigas em português redirecionam (301) em `proxy.ts`.

Consequência para SEO: cada URL tem uma versão por visitante, sem `hreflang`. Aceito por enquanto.

## Onde ficam os textos

```text
messages/
  en.ts, pt.ts, es.ts        junta os namespaces de cada idioma
  en/<namespace>.json         fonte da verdade
  pt/<namespace>.json
  es/<namespace>.json
```

Namespaces: `common`, `nav`, `auth`, `account`, `profile`, `questions`, `payments`, `feed`, `legal`, `errors`, `emails`, `admin`.

`pt.ts` e `es.ts` são tipados contra `en.ts`, e `global.d.ts` registra o tipo no next-intl. Então **o `tsc` falha** se uma chave faltar em um idioma ou se `t("...")` usar uma chave que não existe.

## Como usar

```tsx
// Client Component
const t = useTranslations("payments");
const format = useFormatter();
t("minimum", { amount: format.number(cents / 100, { style: "currency", currency: "BRL" }) });

// Server Component, route handler, Server Action
const t = await getTranslations("errors");
return NextResponse.json({ error: t("unauthorized") }, { status: 401 });
```

- **Interpolação e plural** com ICU (`{count, plural, one {# pergunta} other {# perguntas}}`); marcação com `t.rich`. Nunca concatene pedaços traduzidos.
- **Dinheiro e datas** com `useFormatter`/`getFormatter`. A moeda vem do dado (`questions.currency`: `BRL` ou `USD`), nunca do idioma.
- **Metadata** com `generateMetadata` + `getTranslations`.
- **Services (`lib/services`)** não importam next-intl: o erro carrega uma chave (`new WithdrawError("noPixKey")`) e a rota ou action traduz.
- **Schemas Zod** com mensagem para o usuário são fábricas que recebem o tradutor.

## Adicionar um texto

1. Chave nova em `messages/en/<namespace>.json`, e a mesma chave em `pt` e `es`.
2. `t("chave")` no componente.
3. `bunx tsc --noEmit`.

## Adicionar um idioma

1. Código em `locales` (`i18n/config.ts`) e o nome em `common.locales` nos três idiomas.
2. Pasta `messages/<código>/` com todos os namespaces e `messages/<código>.ts`.

## Testes

- `i18n/config.test.ts` cobre a negociação do `Accept-Language`.
- O Playwright roda com `locale: "pt-BR"` (`playwright.config.ts`): os specs conferem textos em português.
